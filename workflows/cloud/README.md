# workflows/cloud: graphs for standard Comfy Cloud jobs (open weights, core or supported nodes only)

Main-cut decision (Oct 18 2026): real runs go to Comfy Cloud as ordinary workflow jobs. That means API v2 `POST /api/v2/jobs` via `@comfyorg/sdk`, on the Standard plan. Every graph here is our own API-format graph.
- They use only ComfyUI core nodes (`nodes`, `comfy_extras.*`) and model files from the public Comfy Cloud model list (`GET https://cloud.comfy.org/api/experiment/models/{folder}`, read Oct 18 2026).
- They contain no API or partner nodes and no community node packs.
- Built from the ComfyUI node schemas (`/object_info` of our CPU ComfyUI 0.41.0) and the behaviour described in the public Comfy docs and templates. Nothing comes from Higgsfield.

## Conventions (compatible with `server/src/comfy/plans.ts`)

- Local files are bound with `setIn(g, node, field, F(path))` → `{__file}`. The runner turns that into an upload: `ComfyNative.upload` locally, or `client.assets.fromFile` → `core/ASSET` on Cloud. Only loader widgets (`LoadVideo.file`, `LoadImage.image`) take files.
- Upscale graphs keep the existing ids: `18` = LoadVideo, `16` = CreateVideo, `17` = SaveVideo, `15:4` = the seed node. `plans.ts upscale()` also writes `resolution` / `max_resolution` / `batch_size` into `15:4`. On the native graph those keys are ignored (ComfyUI drops undeclared inputs), so **PB needs a cloud branch** that writes the size into `15:5.resize_type.shorter_size`. The ESRGAN graph has no `15:4`.
- H3 graphs are byte-for-byte our local graphs except the one `vae_name`. `nm('h3-t2v')` and `nm('h3-i2v')` can point at `cloud/h3-*-api.json` (`wf()` resolves paths relative to `workflows/`).
- Audio: the upscale graphs pass the source audio into CreateVideo. `muxSourceAudio` in the plan still remuxes locally as before.
