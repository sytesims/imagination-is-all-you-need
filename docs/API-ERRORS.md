## Error body

Most errors are JSON with a human sentence in `error` and a machine category in `errorType`; validation errors add `issues[]` (all problems at once), and many add a top-level `code`. Submit-time errors that cost nothing carry `refund {refunded:false, amount:0, charged:false, note:"Nothing was charged."}`.

```json
{
 "error": "Couldn't read this image. …",
 "errorType": "validation",
 "code": "unreadable",
 "issues": [
  {
   "code": "unreadable",
   "field": "file",
   "message": "…",
   "severity": "block"
  }
 ]
}
```

OpenAPI schemas: `Error` {error, errorType}, `ValidationError` = Error + {issues[]}, `Issue` {code, field, message}. `errorType` enum in openapi.json: `validation`, `invalid_input`, `nsfw`, `ip`, `concurrency`, `credits`, `temporary`, `provider_outage`, `not_cancellable`, `no_provider`, `routing`, `not_found`, `forbidden`, `server`. The server also sends `no_provider`, `routing`, `not_found` (see the scan below). There is no app-side moderation, reporting, suspension or Terms gate: `nsfw` / `ip` only appear when a cloud provider refuses a job.

Not every route follows the shape yet: an unknown tool on submit returns `404 {"error":"unknown tool <id>"}` and an unknown job `404 {"error":"not found"}`, both without `errorType`. Match on HTTP status first, then `code` / `errorType`.

Job-level failures are not HTTP errors: `GET /api/jobs/{id}` returns 200 with `status` `failed` | `blocked` and `errorType` (`temporary`, `provider_outage`, `ip`, `nsfw`, …), plus `refund`. `blocked` means the cloud provider itself refused the job (the app never pre-blocks content); its credits go back to your balance (team mode) once.

| Limit | Value (live 29 Oct 2026, 17:15 (Dubai, UTC+4)) | Notes | Source |

| reference image | 64 MB each | Restyle character refs | server/src/tools/shared.ts |
| media limits | { minSec: 4, maxSec: 30, minPixels: 409_600, maxRefs: 30, refsPerCall: 8, maxPrompt: 10_000 } | Source video seconds, min pixels, refs per job / per call, prompt length | server/src/media.ts |
| image checks | <128 px short side → 400 `low_res`; unreadable → 400 `unreadable`; all-black → 400 `dark` | Warnings only: <512 px, very dark/bright | openapi POST /api/media |

**Rate limits:** there is no per-IP HTTP rate limiter (no rate-limit plugin in server/package.json). The only 429s are the admission checks on job submit, in this order: queue full → (with maxQueued=0) parallel cap. None of them charge.
